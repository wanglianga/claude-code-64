# 暖阳陪诊 · 医院分时到院与检查单引导平台

面向**患者/家属、陪诊员、医院服务台**三类角色的陪诊预约与全程引导系统。
技术栈：**React 18 + TypeScript + Vite + Zustand**，纯前端 SPA（数据经 Zustand `persist` 保存在浏览器 localStorage，无需数据库），生产镜像为非 root 的 unprivileged nginx。

---

## 一、原始需求（原始 Prompt 原文）

> 设计医院陪诊预约分时到院与检查单引导页面，可使用 React、TypeScript 和 Zustand。患者或家属提交科室、就诊人、行动能力、既往病历、检查单、是否需要轮椅、是否空腹和陪诊诉求后，页面生成分时到院建议和材料清单。陪诊员接单后，需要看到挂号时间、楼栋、诊室、缴费窗口、检验检查地点、取药点和可能的排队时长。患者到院后，页面按实际进度引导签到、候诊、医生开单、缴费、抽血、影像检查、回诊和取药；若检查需要空腹、排队过长、患者行动不便、医生临时停诊、检查单缺项或家属远程追问，页面要让陪诊员把当前状态、下一步选择和费用变化同步给家属。就诊结束后，诊断结果、用药说明、复查时间、发票、检查报告领取方式和陪诊评价进入本次服务档案，用于后续复诊提醒和陪诊员服务质量评估。页面还要把医院楼栋复杂路线、报告出具时间、陪诊员换班、患者情绪安抚和家属远程授权合在一起，呈现一条能被现场执行的就医行程。如果患者需要跨院区检查，页面还要管理交通方式、报告互认、陪诊费用变化和预计返院时间，避免就医路径中途断开。

## 二、需求覆盖对照

| 需求点 | 实现位置 |
| --- | --- |
| 提交科室/就诊人/行动能力/既往病历/检查单/轮椅/空腹/诉求 | 家属端「提交陪诊预约」表单（`FamilyHome.tsx`） |
| **分时到院建议** | `plan.ts → buildAdvice()`：综合空腹、行动能力、科室高峰、检查排队时长、上下午时段，算出建议到院/挂号时间与逐条依据，表单右侧实时预览 |
| **材料清单** | `plan.ts → buildMaterials()`：按空腹/轮椅/MRI/慢病等动态生成必备/建议清单，可勾选核对 |
| 陪诊员接单看到挂号时间、楼栋、诊室、缴费窗口、检验检查地点、取药点、排队时长 | 陪诊员抢单（`EscortHome.tsx`）→ 接单后「陪诊执行台」任务要点卡（`EscortConsole.tsx`） |
| 到院后按进度引导签到/候诊/开单/缴费/抽血/影像/回诊/取药 | 执行台阶段时间轴 + 8 环节逐步推进（`advanceStage`），每环节含地点、实际排队录入、备注 |
| 空腹/排队过长/行动不便/停诊/缺项/家属追问等异常 | 10 类异常模板（`store.ts → INCIDENT_TEMPLATES`）：当前状态描述、下一步选项、费用变化、是否需家属授权 |
| **医生临时加开空腹抽血/胃镜** | 陪诊端「🍚 临时空腹加项」：只录入**末次进食日期+钟点**，空腹时长由系统盖戳时钟实时派生（**不能手填**；晚于当前时刻自动改判昨日并留痕）→ 生成**继续等待/改日检查/先完成其他项目**三方案，继续等待/改日/先做其他的**缴费、取号、回诊均由同一核查结论整体重算**；刚进食或未满禁食时长时「继续等待」不可选；回诊受影响时**锁定回诊，必须先联系医生助理确认**；选改日则当日回诊自动顺延 |
| **轮椅/平车转运协同** | 陪诊端「♿ 轮椅/平车转运」：按订单科室**院区锁定**起终点（总院/东院各自独立的**无障碍路线、电梯位置、距离、拥堵提示、预计耗时、志愿台电话**：总院 8001 / 东院 8101）；**路线库未配置的组合（含跨院区误选）不回退其他院区路线，直接阻止创建**（按钮禁用+store 二次拦截），转运记录/家属提示/押金/费用均不写入，提示补充路线配置；拥堵时联系志愿台或调整顺序错峰；卧位自动切平车+预约医梯，结合能否独立如厕、家属是否随行生成现场记录；租借/转运费入账、押金可退不计应缴 |
| 陪诊员同步当前状态、下一步、费用变化给家属 | 「一键状态同步」（结构化当前阶段+排队+累计费用）+ 家属—陪诊员实时消息面板 |
| 家属远程授权 | 异常触发授权卡 → 家属端「远程授权」批准/拒绝 → 通过后费用入账、异常解锁闭环 |
| 诊断/用药/复查/发票/报告领取/评价 → 服务档案 | 执行台「结束归档」→ 家属端查看档案并星级+标签评价 |
| 复诊提醒 | 服务台按复查日期计算逾期/今日/3 天内并标记推送（`DeskHome.tsx`） |
| 陪诊员服务质量评估 | 服务台：平均星级、评价标签、单量、未闭环异常、金牌/优秀评级 |
| 楼栋复杂路线 | 每个订单生成 8 步可执行院内动线（连廊、医梯、无障碍坡道、采血/影像/取药点），**按订单院区生成**：东院全程为东院路径（遮雨连廊 180 米、东院医技楼医梯、东院收费/药房），总院为总院路径（260 米、空中连廊）；转运的路线/电梯/志愿台/拥堵分流/家属通知均从同一院区信息派生（总院 8001、东院 8101），不混用 |
| 报告出具时间 | 按所选检查最长 `reportHours` 自动估算（如 CT 24h、MRI 48h、血常规 1h） |
| 陪诊员换班 | 发起换班（接替人/原因/交接清单）→ 家属知悉确认，服务不中断 |
| 患者情绪安抚 | 异常类型「情绪安抚」+ 独立安抚记录时间线，同步家属 |
| **跨院区检查** | 交通方式（班车/打车/救护转运）、交通费、跨区陪诊费、报告互认、发车与**预计返院时间**、出发/到达/返院状态推进 |
| 费用变化 | 全量费用台账（挂号/检查/药费/交通/陪诊/转运/退费），异常加收与停诊退费均经授权后入账；轮椅/平车押金为可退款项，不计入应缴 |

## 三、一键启动（Docker Compose）

前置：宿主已安装 Docker 与 Docker Compose 插件。**无需**在本机安装 Node。

```bash
# 1. 准备环境变量（可选，评估环境已注入 CC_PUBLISH_PORT / COMPOSE_PROJECT_NAME）
cp .env.example .env

# 2. 构建并后台启动（多阶段构建：node:22-alpine 构建 → 非 root nginx 运行）
docker compose up -d --build

# 3. 查看实际映射端口（不要假设固定端口）
docker compose port app 8080
# 例如输出 0.0.0.0:3064，则浏览器访问 http://<宿主IP>:3064
# 在同一台 Docker 主机内可用：http://host.docker.internal:3064

# 4. 查看健康状态（STATUS 应显示 healthy）
docker compose ps

# 5. 验证结束后释放资源
docker compose down
```

容器内应用以 **uid=101 非 root 用户**运行，监听 **8080**（非特权端口）；
compose **只发布 app 一个服务端口**到宿主（`${CC_PUBLISH_PORT}:8080`），本应用无数据库/缓存等依赖服务。
镜像内置 `HEALTHCHECK`（wget 探测 `/`）。

### 验证方式 = 宿主 docker compose up

1. `docker compose up -d --build` 后 `docker compose ps` 中 app 为 `healthy`；
2. `curl -fsS http://127.0.0.1:$(docker compose port app 8080 | cut -d: -f2)/` 返回 `index.html`；
3. 浏览器打开宿主端口，用下方演示账号登录走通「预约 → 接单 → 到院 → 异常/授权 → 跨院区 → 归档评价」全流程。

## 六、目录结构

```
src/
├── types.ts            # 全部领域模型（订单/阶段/异常/授权/跨院区/换班/档案…）
├── data.ts             # 院区/科室/检查目录（地点·空腹·报告时长·费用·排队）/陪诊员/账号
├── plan.ts             # 分时到院算法、材料清单、执行点与院内路线、费用、跨院区方案、空腹核查时间源
├── transfer.ts         # 院区点位与院内无障碍路线库（总院/东院）、电梯、押金、耗时、拥堵、缺失拦截
├── store.ts            # Zustand store：订单全生命周期 + 10 类异常处置模板 + 转运/空腹加项 + 种子数据
├── ui.tsx              # 通用组件：状态徽章/阶段时间轴/材料清单/费用表/家属同步面板
├── App.tsx             # 角色路由与外壳
├── LoginPage.tsx       # 三角色登录
└── pages/
    ├── FamilyHome.tsx      # 家属：预约表单 + 方案实时预览 + 我的陪诊单
    ├── FamilyOrder.tsx     # 家属：方案/路线/行程/远程授权/同步/转运/跨院区/档案评价
    ├── EscortHome.tsx      # 陪诊员：抢单队列 + 我的订单
    ├── EscortConsole.tsx   # 陪诊执行台：阶段引导/转运/空腹加项/异常/跨院区换班/同步费用/归档
    ├── TransferPanel.tsx   # 轮椅/平车转运协同（院区锁定、路线/电梯/押金、拥堵、卧位）
    ├── FastingAddonPanel.tsx # 临时空腹加项：进食核查（系统时钟）与三方案处置
    └── DeskHome.tsx        # 服务台：实时总览/复诊提醒/质量评估/档案库
```

> 说明：业务数据（订单、消息、授权、档案、转运、空腹核查）存于浏览器 localStorage（key: `warm-sun-escort-v3`），用于单机演示完整业务闭环；服务台页提供「重置演示数据」。
